# 네이버 날씨 홈 위젯 플러그인 (v1.4.0)

## 설치
1. 이 `naver_weather` 폴더 전체를 BookOasis 서버의 `plugins/metadata/` 아래에 복사합니다.
   ```
   plugins/metadata/
     naver_weather/
       __init__.py
       naver_weather.py
       VERSION
       requirements.txt
   ```
2. 서버를 재시작합니다. (`requirements.txt`의 `requests`가 자동으로 플러그인 전용 `libs/`에 설치됩니다.)
3. 환경설정 > 플러그인 설정에서 "네이버 날씨 위젯"을 활성화합니다.
4. 아래 "지역 설정" 안내에 따라 **REGION_CODE**를 입력하고 저장합니다 (강력 권장).

## 지역 설정 (중요 — v1.0.0에서 바뀐 부분)

v1.0.0은 "지역명 검색" 방식이었지만, 실제 네이버 날씨 페이지(`weather.naver.com/today`)를
확인해보니 이 페이지는 **검색 쿼리 텍스트가 아니라 접속 세션/IP 기준으로 이미 정해진 지역**의
날씨를 보여주는 구조였습니다. 그래서 지역명만으로는 원하는 지역의 날씨가 정확히 나오지
않을 수 있습니다.

**해결책: REGION_CODE(지역 고유 코드)를 직접 찾아서 입력하세요.**

1. 브라우저로 https://weather.naver.com 에 접속합니다.
2. 우측 상단 검색(돋보기)으로 원하는 지역(예: "광주광역시 광산구")을 검색해 선택합니다.
3. 주소창의 URL이 `https://weather.naver.com/today/18330600` 같은 형태로 바뀝니다 —
   마지막의 숫자(`18330600`)가 REGION_CODE입니다.
4. 이 숫자를 플러그인 설정의 **REGION_CODE** 항목에 그대로 입력하고 저장합니다.

REGION_CODE를 입력하면 LOCATION(지역명) 설정은 화면 표시용 라벨로만 쓰이고, 실제 데이터
조회는 REGION_CODE로 정확하게 이루어집니다.

### REGION_CODE를 입력하지 않으면?
플러그인이 네이버의 비공식 지역 자동완성 API로 지역명을 코드로 변환해보려고 시도합니다.
다만 이 API는 문서화되어 있지 않아 언제든 응답 형식이 바뀔 수 있고, 실패하면 위젯에
"정보를 불러오지 못했습니다" 안내와 함께 REGION_CODE를 직접 입력하라는 힌트가 표시됩니다.
따라서 정확도를 원한다면 처음부터 REGION_CODE를 입력하는 것을 강력히 권장합니다.

### CACHE_TTL_SECONDS
기본 600초(10분) 동안은 같은 결과를 재사용해 네이버에 과도하게 요청하지 않습니다.

## 홈 화면에 노출하기
`home_widget` 계약을 사용했기 때문에, **사용자가 "내 설정 > 홈 화면 플러그인 배치 모드"를 켜야**
홈 화면 하단의 "+ 위젯 추가" 목록에 이 위젯이 나타납니다. 목록에서 선택해야 실제 홈 화면에
카드로 추가됩니다(설치만으로는 자동 노출되지 않음).

## v1.4.0에서 바뀐 점: 메인 카드에 정보 통합

이전 버전은 최저/최고·습도를 각각 별도 카드로 보여줬지만, v1.4.0부터는 **날씨상태 ·
현재기온 · 최저/최고 · 습도**를 메인 카드 하나(설명란)에 모두 묶어서 보여줍니다.

예시: `광산구 월곡1동` / `20.7°` / `맑음 · 어제보다 0.3°↓ · 최저 18° 최고 29° · 습도 89%`

이에 맞춰 `SHOW_RANGE`/`SHOW_HUMIDITY` 설정의 의미도 바뀌었습니다 — 이제 "별도 카드
표시 여부"가 아니라 **"메인 카드 설명란에 최저/최고·습도를 포함할지"**를 제어합니다.
체감온도·바람·미세먼지·초미세먼지·일출·일몰은 이전처럼 각각 독립된 카드로 유지됩니다.

## v1.3.0에서 추가된 정보: 카드별 표시/숨김

환경설정 > 플러그인 설정 화면에서 아래 8개 카드를 각각 체크박스로 켜고 끌 수 있습니다
(위치+현재기온 메인 카드는 위젯의 핵심 정보라 항상 표시됩니다):

- `SHOW_RANGE` — 최저/최고 기온
- `SHOW_FEELS_LIKE` — 체감온도
- `SHOW_WIND` — 바람(풍향/풍속)
- `SHOW_HUMIDITY` — 습도
- `SHOW_PM10` — 미세먼지
- `SHOW_PM25` — 초미세먼지
- `SHOW_SUNRISE` — 일출
- `SHOW_SUNSET` — 일몰

전부 기본값은 켜짐(true)이며, 체크 해제하면 해당 카드는 홈 위젯에서 사라집니다. 데이터
자체가 없는 항목은 체크되어 있어도 자동으로 건너뜁니다.

## v1.2.0에서 추가된 정보

홈 위젯은 코어의 공용 카드 렌더러(라벨-값 형태)만 쓸 수 있어 네이버 앱과 완전히 동일한
비주얼(원형 해 아이콘, 큰 숫자 등)은 재현할 수 없지만, 그 형태 안에서 아래 항목을 모두
개별 카드로 추가했습니다:

- 위치 + 현재기온 (날씨상태·어제 대비 기온차를 설명란에 함께 표시)
- 최저/최고 기온
- 체감온도
- 바람(풍향 + 풍속)
- 습도
- 미세먼지 / 초미세먼지 등급
- 일출 / 일몰 시각

값이 없는 항목은 자동으로 건너뛰므로, 데이터 응답에 따라 카드 개수가 달라질 수 있습니다.

## 동작 방식
- `weather.naver.com/today/{REGION_CODE}` 페이지를 서버에서 가져옵니다.
- 이 페이지는 화면에 보이는 HTML 태그가 아니라, 페이지 안에 인라인으로 삽입된
  `var blockApiResult = {...};` 라는 거대한 JSON 변수에 현재기온·날씨상태·체감온도·
  미세먼지 등 모든 실데이터를 담고 있습니다. 이 JSON을 직접 파싱해서 값을 추출합니다
  (`nowSynthesisFcast` 블록의 `nowFcast`/`airFcast`).
- **네이버가 이 JSON 구조나 변수명을 바꾸면 파싱이 깨질 수 있습니다.** 이 경우 위젯은
  에러 대신 "정보를 불러오지 못했습니다" 안내만 표시하도록(fail-soft) 만들어져 있습니다.
  계속 안내만 뜬다면 `naver_weather.py`의 `_extract_block_api_result()` /
  `_parse_weather()`를 최신 페이지 구조에 맞게 업데이트해야 합니다.
- 외부 사이트 스크래핑이라는 특성상 네이버 이용약관/요청 빈도 정책을 참고해 캐시 TTL을
  너무 짧게 두지 않는 것을 권장합니다(기본값 10분).
